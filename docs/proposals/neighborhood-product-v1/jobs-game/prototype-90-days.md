# 90-day prototype: Snow Plow + Paper Route

Start after Builder/WorldEngine can provide a stable real street scene. Two manually selected curated districts: Denver and Chicago. Internal adult testing only. This is not permission to recruit, publish, message players or launch a service.

## Days 1–15: one enjoyable minute

Build tiny plow coverage and paper-flight experiments on real mapped road/walk geometry. Standard plow, bike/walk paper mode, no people. Establish mask IDs, surface saves, generic front-walk points and camera/control variants. Validate trigger schema with synthetic fixtures and archived observed snow events. Read inherited calibration-v2 look and foliage-season rules. Prototype objective: clearing and tossing feel satisfying before an economy is added.

Decision: internally observed testers choose to repeat both actions and can distinguish fictional customers from residents. Fix any privacy misunderstanding before expanding. Actual prototype cannot claim surveyed targets merely because a map shows a house.

## Days 16–35: complete local loop

One 5–12 minute authored route per job per city; pick → route → action → fixed reward → local workshop. Assist mode, pause/resume, missed-paper retry, no timers/energy. Save clearing masks and daily completion locally. Earn one paint colour and one nonessential handling/tool choice; no store/payment.

Acceptance: 10 repeated save/reload cycles retain identical completed segment coverage; feed replay is idempotent; no additional credits from duplicate completion; 100 fixture tests cover new snow/melt/revisions, stale feed, no-snow, dawn and DST. Instrument game state in local test harness only, not user location telemetry. Confirm street-mesh, road-lane and frontage masks before target placement.

## Days 36–55: live environmental adapter

Wire candidate public environment sources behind a broad-area privacy cache/relay. Source timestamp, observed/analysis/model class and unknown state visible. New snowfall requires credible past snowfall data, not forecast. Source quality/time and observed event creation need explicit validation. Compare Denver and Chicago sample events against independent available snowfall reports; street-level certainty is never claimed. Live mode plus separately labeled archived practice resolves a snow-free prototype calendar.

Acceptance: forecast-only, snow-depth-only, missing and revised data fixtures behave as specified; daybreak calculates each city/timezone correctly. Network/log audit contains no resident, home, exact player position or identity-to-area history. Data licence review and privacy review are release dependencies.

## Days 56–75: cooperative snow day and progression test

Add Common Ground district goal with synthetic aggregate bands first. Real anonymous contributions only after a specialist approves protocol, private thresholding and release budget. No named players, public street-clearing map or live counter. Test two short route variations and a fixed-price cosmetic concept; Gather stays a link to existing secondary UX, not new event machinery.

Directional internal study: at least 20 consenting adults, balanced between Denver/Chicago content; opt-in questionnaires and observed sessions, no movement tracking. Proposed gates: ≥70% call an action satisfying, ≥40% voluntarily return within seven days without reminders, ≥8/10 explain no resident/customer data. These are small-sample decisions, not statistically validated retention claims. Collect explicit feedback on weather authenticity versus availability friction.

## Days 76–90: phones, persistence, decision

Verify real devices at 320/390/430 equivalent layouts plus supported large text and screen readers, steering/tap assist, reduced motion, background/resume, battery/memory and offline save. Target 30 fps on the agreed low/mid-range phone and responsive inputs; unverified performance target, never claimed by these artwork mocks. Snow/material masks fit within the existing scene budget, not an extra allowance. Audit logs, tile requests and co-op surfaces again.

Continue if plowing/paper game feel, voluntary repeat, data reliability, privacy and mobile budget all hold. If snow availability dominates frustration, expand Paper Route and archived practice while keeping live snow honest. If enjoyment requires resident simulation or player tracking, reject that direction. Do not expand into ten shallow jobs before proving two deep ones.

## Staffing and scope boundary

Proposed: gameplay/client engineer, shared engine engineer, product designer, part-time environment-data engineer and privacy/security reviewer. Actual staffing/costs unverified. Deliverables: two cities × two job route slices; standard tools and free assists; local save/credits; two earned cosmetics; honest event gating; synthetic shared-goal UX. No payments, public launch, messaging, residents, crowds, GPS, routing people, commercial deliveries, multiplayer driving, cloud home saves or real-world service claims.

Mowing, leaves and other catalogue jobs are concept-only during these 90 days. Paid cosmetics/pass remain pricing and willingness-to-pay hypotheses. Common Ground and Gather stay secondary, unchanged outside this new folder.
