# Privacy and data boundary

The real neighbourhood supplies geography and environmental context only. It does not supply people.

- No real residents, names, account-linked houses, occupancy, household schedules, doorbell/camera observations, utility status or actual deliveries. Customer and job generation never uses resident data.
- Home location is not needed in v1. Any later convenience stays device-only, encrypted, excluded from cloud backup, analytics, logs, map exports and server queries. The fictional workshop has no residential map anchor.
- No GPS permissions, individual tracking, physical-route recording, live presence, heatmaps, social street-clearing maps or geofenced rewards. Playing an in-game route is not telemetry about a person's movement. Local game traces are not uploaded.
- Location is manual broad area selection. Fetch broad public environment data through a privacy relay/cache without account identifiers; turn off identifying network request logs. A weather query can leak area interest if attached to an account or IP history. No server identity-to-area table.
- Saves and earnings stay local; exports omit addresses, exact job stops and metadata. Prototype uses local browser state, no backend or external messages.
- Opt-in co-op sharing starts off. Proposed anonymous event token carries a capped completion unit, never street/house ID, exact time, device ID or identity. Delayed fixed weekly releases, broad district, minimum 30 distinct contributors, coarse bands, private threshold checks and a reviewed differential privacy budget. These are design proposals, not a privacy proof. No arbitrary filtering or overlapping query releases. Suppress sparse cohorts.
- No user profiles, messages, rosters or social graph in prototype. Adult audience, no dogs, pets, mascots, host-app content or school tasks. Adult age assurance and privacy/security review remain release work.
- World artwork is stylized game imagery. Windows and home lighting cannot encode occupancy. Snow-clearing states are game-only; never imply actual street service status.

A data freshness/permission label is part of every job eligibility decision. Unknown current conditions cannot masquerade as observed. Server analytics must not recreate play routes. Use opt-in internal research questionnaires outside the product rather than passive individual telemetry.
