# Master tracker update rules

These three systems are the research index, coverage workbook/CSV sheets, and monument workbook/CSV sheets. Existing sources remain read-only; tracker edits require their own authorized scope.

## New pack

Read README, values, manifests and all source tables. Inventory files. Superseded folders establish history only, never current authority. Add one canonical entry with date/type/status/style/findings and real file links; link filed copies rather than duplicate them. Keep Style C illustrated concepts separate. Approval of an input never approves a new output.

Update country/city coverage only from evidence. Recommended countries are next/candidate, not live. Named proposed areas are not engine tests. Eight shared Japan typologies are not eight per city. Preserve exact observation/release dates and unknown completeness.

Add dataset/product rows with app display, storage/cache, raw redistribution and World State API rights separated. GREEN is conditional on selected product/use/attribution. Missing/conflicting evidence is YELLOW. Some source-pack RED labels mean no verified resource or permission, not legal prohibition; retain the explanation. Never record sent outreach without dated sent-message/response evidence; tracker upkeep alone does not authorize contacting anyone.

Merge monument identities by original IDs and explicit aliases. Empower LM-DEN-STADIUM = LM030; Hard Rock LM-MIA-STADIUM = LM036. Day/night/season/camera/filed variants are one place. Distinct components/campuses need explicit scope. Similar names are not enough for a merge. Preserve actual municipality; University Park requires Florida/Texas disambiguation. Metro-only associations stay unresolved and are excluded from distinct-city counts.

Include named landmark-like strategic candidates (stadium/arena, campus/civic, park, monument, bridge). Other place lists such as airports/hospitals/malls are not automatically monuments. Generic precinct gates, fictional skylines and kit control-tower/stadium modules are excluded. Keep original source type alongside the requested eight normalized types; civic is a broad catch-all, not architectural/legal reclassification. Rights-example places remain researched unless selected/designed evidence exists.

Inside-test-area Y records a documented named association, including proposed/review areas; describe its scope. N means inclusion not evidenced, not surveyed outside. A distant landmark seen from a test is not automatically inside. Exact polygon membership needs a separately recorded intersection.

## Stage changes

Independent milestone flags preserve evidence arriving out of order. Pipeline stage is the highest consecutively evidenced gate: researched → designed (Style B sheet) → approved → height verified → built in engine → verified in engine. Do not fabricate prerequisites to fit the sequence.

- Researched: named identity/scope and pack reference.
- Designed: named-place Style B specification/reference sheet; generic kit or area-inspired scene alone is not a monument sheet.
- Approved: explicit dated owner/controlling approval of that exact output and scope. Approved inputs, inherited JSON and prompt text do not prove output approval. Appearance approval is not geometry or rights clearance.
- Height verified: reconciled component/endpoint/source/date/ground-datum evidence and appropriate uncertainty. Published top heights, OSM tags, storeys and spire conversions with unresolved roof/bowl parts do not pass the full gate. District/park/natural N/A needs a documented terrain/component verification gate, not an invented scalar.
- Built in engine: stable asset/feature ID and actual named runtime appearance in a recorded area/package/build. Generic city extrusion, generated HTML/PNG or data relay implementation is insufficient.
- Verified in engine: acceptance evidence for that exact build, covering geography/scale/recognition/style and relevant device results. Changed/superseded builds need re-verification.
- Record downgrade/revocation date, reason and prior evidence in notes. No pack lands automatically approved/built.

## Workbook and CSV refresh

Update Monuments detail first. Summary formulas read independent milestones and exclusive current stage. Never manually type marketing totals. Country/city/type group matrices reconcile stages and milestone counts; unique city counts exclude unresolved municipality placeholders.

Extend tables and every bounded formula range when adding rows. Add new country/city/type groups. Recalculate; reconcile IDs, original 100, alias merges, total rows, stage totals, public eligibility and unique geography counts. Re-export every worksheet as UTF-8 CSV values after any saved workbook change. CSV snapshots must not diverge from workbooks. Preserve validation lists, freeze panes and status conditional formats.

## Public claim gate

Only built-in-engine and verified-in-engine counts may be used publicly, with exact labelled scope and evidence. Researched, designed, approved and height-verified counts are INTERNAL ONLY. Stage eligibility is necessary, not rights clearance: resolve relevant rights and stale-build exclusions before publication. Do not call concepts production models or researched feeds live integrations.

Current snapshot has zero evidenced named engine builds and zero engine-verified monuments. Zero describes these inspected inputs, not all possible work elsewhere.

## Source protection

Modify only this tracker folder unless separately authorized. No git. Before future authorized tracker maintenance, retain a dated tracker snapshot in this folder. Source files remain unchanged. Support inventory/builders live in .work and are not new evidence. Standing mock rule: no dogs, characters or host-app content unless explicitly requested.
