# Add a city — map-only runbook

8 Oct 2026 · Execute through the owning lanes. This procedure records existing gates; it authorizes no downloads, source approvals, phone installs or release. Start with a bounded area, not an assumed whole-metro rollout.

1. **Check the exact source and intended use — A1, using A5 research.** Read [country-readiness-v1](../research/country-readiness-v1.md), the [metro inventory](../research-gpt/metro-data-coverage-v1/README.md) and [licensing/credit decisions](../data-licensing.md). Pin the selected product/release/tile licence, redistribution conditions, required credits and unresolved rights. A5's Amsterdam → London → Toronto recommendation is not ingestion approval; estimates are not measured coverage. Use only sources cleared GREEN for the intended ingestion; keep unresolved routes blocked and record the question. Do not infer source permissions from a national label or another theme's licence. Public package distribution has its own unresolved release gates.

2. **Freeze authorization and area — A1 with R.** Choose a stable area ID, explicitly approved bounds, configured buffer and intended test views. Record authorization in the existing area configuration. [prepare_area.py](../../Tools/regionkit/prepare_area.py) requires `processingStatus=AUTHORIZED`, refuses existing-area replacement and uses OSM `out body` without contributor metadata. Do not turn HOLD into authorization, expand a rectangle silently, or reuse a personal location. Retain source dates, notices and hashes. Check disk/storage scope before acquisition.

3. **Select the general adapter — A1.** Follow [A1's tracker](../tracking/a1-data.md), [lidar pipeline](../../Tools/regionkit/lidar/README.md), [terrain pipeline](../../Tools/regionkit/terrain/README.md) and A5's adapter assessment. Verify actual format, tile overlap, coordinate system, vertical datum, resolution, survey age and classification support. Reuse common methods after normalization; add a general source adapter when required. Do not claim the US survey loader runs unchanged on a different national format. Missing year-built/roof information stays null; DSM minus DTM is not automatically a measured roof form.

4. **Prepare and validate area evidence — A1.** Use the authorized preparation workflow, then the documented [heights](../data/building-heights.md), [roofs](../data/building-roofs.md) and [elevation](../data/elevation.md) pipelines where supported. Preserve observed versus estimated labels and uncalibrated support scores. Run the corresponding tests/verification and [area-size checks](../data/area-size-budget.md). Heavy builds/full tests/rendering and verification requiring the owner lock use `scripts/heavy.sh`; never alter another lane's lock. Record missing tiles/NoData and failures rather than synthesize passing coverage.

5. **Prove data transfer on hold-outs — A1 → A3/P2.** Run the same general method on the target and the applicable existing comparison areas; record configuration differences limited to authorized source/region inputs. Publish denominators, accepted/missing counts, dates, units/datums and quality/invariant failures alongside Sloan's. Existing examples live in `Data/quality/height-holdouts.json`, `roof-holdouts.json` and `elevation-holdouts.json`; they demonstrate reports for their named areas, not readiness of this new city. Handoff exact files and limitations. Do not present data QA as a visual score.

6. **Generate and export — P2/5A content, A1 package owner.** Select approved regional profiles and source tags through the existing WorldBuild path. Cite [proposal INDEX](../proposals/INDEX.md), pack keys and [pack usage](../pack-usage.md); pending concepts cannot silently become binding defaults. Follow [package-format.md](../package-format.md) and the existing `scripts/export-package.sh` / worldbake export workflow with the intended area/recipe. Validate package hashes, bounds/units, feature IDs, source metadata, credits and `LICENSE-DATA.md` with `Tests/WorldPackageTests/`. Ensure generated details remain labelled/inferred; a successful export does not establish look parity or budget compliance.

7. **First render — renderer owner, then A3.** Render the same approved area/recipe in the intended renderer: RealityKit through its in-process WorldBuild path, or the package consumer for web. A2 changes stay in `web/bakeoff/`; production web ownership needs confirmation before edits. Verify loading, location/orientation/scale, missing-data behaviour and visible OSM attribution. Freeze a camera, viewport, date/season, weather and target before grading. Log commit, input hashes, capture path and device/tier; keep pictures gitignored. Measure relevant main/shadow/draw/memory budgets; laptop evidence is not phone qualification. No camera-specific tuning to rescue the first frame.

8. **First hold-out score — A3.** Use [weekend-brief scoring commands](../tracking/weekend-brief.md#scoring-one-handoff-to-a3-after-each-look-change), [§M/§N](../lookloop/GRADING.md) and [look-gate tracker](../tracking/look-gate.md). Record the new area's baseline and available untuned Sloan's/Lakeview/Wilmette comparisons as applicable to that renderer. Freeze any newly added Denver/Greenville capture before use; unavailable views remain pending. Score closeness and all six aspects, with each existing view's before/after. Reject-flag Sloan's improvement paired with hold-out loss; neither a two-view result nor a new-city baseline clears the full four-hero gate. Keep web and iOS separate; changed conditions require an explicit comparison caveat or new baseline.

9. **Record delivery and merge — owning lane, A3 records.** Add the source/area readiness, package version, render evidence, budget results and score links to [handoffs](../tracking/handoffs.md), [A1 tracker](../tracking/a1-data.md) and existing [country](../proposals/master-trackers-v1/coverage-by-country-Countries.csv)/[city](../proposals/master-trackers-v1/coverage-by-country-Cities.csv) trackers through the filing lane. Distinguish data delivered, package validated, first render and look passed. Rebase on main, rerun affected checks and the commit-size guard, then follow the authorized merge process. Resolve only add-only handoff conflicts by retaining both dated entries; stop on other conflicts. Before distribution, satisfy the documented public data-offer/credit and other release gates; filing or merging is not publication approval.
