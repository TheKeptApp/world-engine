A8 independent audit — prototype `34f8a7f`, default OFF; source and saved JSON inspected, small CPU geometry/estimator witnesses run without rendering; no captures or code changes. Findings ranked below; no approval to promote the prototype.
BLOCKS A PORT — per-tree culling is not universally conservative: `web/bakeoff/crown-v3.js:63` transforms only level-0’s bounding sphere before choosing any LOD; lower LODs are independently generated and can exceed it. CPU sampled alpha-surviving points for `fraxinus_pennsylvanica`, seed `crown-v3/fraxinus_pennsylvanica`, full leaf, tiny LOD exceeded the near sphere by 0.00737247 normalized units (0.0737 m at scale 10), so a tangent frustum plane can reject visible foliage. The sphere also omits world.root’s transform. Use a union envelope over all selectable LODs with the complete world transform; test accepted patch points at frustum planes. This is a general witness, not a claim that the saved Sloan frames visibly pop.
MISLEADS A DECISION — motion safety is unproven: `web/bakeoff/main.js:140` calls updateLODs once; the animation loop at `:145` never refreshes it after camera/projection changes. The wrapper at `crown-v3.js:61` does refresh when called, but its test does not establish live-camera integration. LOD thresholds have no hysteresis/crossfade (`:10`, `:63`), and projected height uses Euclidean distance to the tree base, not view-space depth/envelope, so screen-edge/off-axis LOD selection can be premature. Static frozen cameras avoid the stale-membership problem; do not promote it to a moving viewer without update and edge controls.
MISLEADS A DECISION — “card layers” count triangle samples, including both sides of shared triangle edges (`web/bakeoff/crown-v3.js:84`); a single square card, two triangles, orthographic 8×8 crop, fully surviving UVs produced 72 hits/64 pixels, average 1.125 and peak 2 although only one card exists. Use a top-left raster rule or per-card/sample deduplication before treating >6 counts as physical card overlap. Uint16 hits can also wrap; `nearClippedTrianglesOmitted` is initialized to zero and never changed (`:73`, `:90`), so asserting zero is not evidence that a near-plane witness was tested.
QUALIFIED PASS — clipping uses all six WebGL homogeneous planes and interpolates UV at clip intersections (`web/bakeoff/crown-v3.js:79`); reciprocal-w interpolation at `:84` matches the shader’s smooth UV field at `:43`–46. CPU accepts radius equality whereas shader uses strict less-than, and floating-point/sample conventions differ. It excludes opaque interiors/wood, scene/depth occlusion, MSAA and helper samples, as reported (`web/bakeoff/evidence/crown-v3/REPORT.md:39`); call it a pre-depth pixel-centre patch estimate, not an upper bound on GPU invocations or total fragments. Saved averages independently equal accepted/covered: 2.34538, 2.21191, 1.74647; peaks 13/17/9 inherit these estimator limitations.
PASS — absent/off cannot dynamically import or install crown-v3: flag validation at `web/bakeoff/main.js:30`, gated import at `:80`, estimator gated on v3 AND capture at `:142`; no static crown-v3 import. `web/bakeoff/shadow-casters.js:25` selects the original material unless group.crownV3 is true. Native and web/src renderer files are unchanged by 34f8a7f. OFF does add flag validation/metadata and explicit --crownV3 off changes capture filenames (`scripts/capture_web.mjs:44`, `:98`, `:104`), but no crown-v3 assets, geometry or shader nodes enter that rendering path; frame-identity claims are not needed for this conclusion.
MINOR / HYPOTHESES — no city/block/coordinate/camera-ID special case found in crown-v3 construction; species-kind branches are general (`web/bakeoff/crown-v3.js:24`, `:53`), capture ladder is an evaluation fixture. Many choices are explicitly prototype ratios, but the report is not exhaustive: layer heights .53/.16, angular jitter .6, lobe anisotropy .8/.4/.7/.5, patch tilt .3/.95, plane offset .28, rim .12/.07, normal mix .65 and cutout .86/.065/.035 with frequencies 7/11 (`:24`, `:34`–45) are hand-authored hypotheses, not measured pack values; document them together. StableRandom’s integer sequence is deterministic (`web/bakeoff/stable-random.js:2`–4); install seeds by species, not tree ID (`crown-v3.js:57`), so same-species geometry repeats with individual transforms/tints. Same-input same-runtime geometry is repeatable; Math trig, float rounding and shader execution leave cross-device bit-identical geometry/pixels unproven.
