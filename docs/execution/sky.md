Replace density-as-brightness with `cloudRGB=mix(linear(shadeHex),linear(litHex),clamp(dot(Ncloud,Lsun),0,1))`, using outward shape normals and direction toward sun in the same world basis. This interpolation is an implementation proposal using approved endpoints, not a new intensity knob. At dot≤0 output shade endpoint; at dot=1 output lit endpoint. Coverage/alpha remains separate and targets 0.18 by the existing documented sky measure; report pixel vs solid-angle coverage, never silently interchange them.

For existing analytic web ellipsoids, derive Ncloud from the ellipsoid implicit-surface gradient; retain front surface facing the outward sky viewing ray, transform to world direction with the panorama basis. At overlapping lobes use the lobe selected by the existing density maximum; no random normal field. Native procedural cloud field has no proven equivalent ellipsoid normal: derive a coherent shape gradient from its existing field only after documenting the coordinate basis and finite-difference interval tied to its existing texture/sample spacing. If that surface cannot be established without a new cloud model or unapproved scale parameter, native shape relighting is **blocked**, retain the native baseline and hand off the missing construction specification. Do not invent a sphere normal from screen coordinates.
