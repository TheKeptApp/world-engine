# World scoreboard v0

## Run and outputs

Run `scripts/world-scoreboard.sh` from a checkout with held `Data/areas` sources. This finite, manual command builds the existing exporter, exports each selected block, captures 40/150/600 m, writes `docs/scoreboard/world-scoreboard-v0.json` and its Markdown table/failure list/diff. It uses the existing output JSON as the previous run **before** replacing it. Use `--previous path/to/prior.json` and/or `--output path/to/run.json` to retain separate run files. PNGs and raw logs stay local under `.build/world-scoreboard/<run ID>/`; commit the JSON/report, never those PNGs. A fresh clone without ignored held sources reports them missing; it does not fetch them.

Every build/export/capture uses `scripts/heavy.sh`; the coordinator does not nest wrappers or hold a lock across blocks. Preparation has its own admission; each block exports and captures its ladder in one admission, releasing before the next block. Load must be below 25, disk free space at least 8 GiB. Each operational step has at most two attempts and a process-group watchdog (preparation 1,800 s; block 1,200 s); a second failure stops and preserves a partial JSON/report with the exact log error. Metric failures are evidence, not operational retries. No schedule, background recurrence, auto-merge, data fetch, renderer/exporter/look change, or human grade is part of this command.

## Deterministic block selection and types

Select **every** `Data/areas/*/manifest.json` with a unique matching area ID and available, manifest-hash-valid core OSM `all` sources; sort by ID. Verify all manifest source hashes and record every local area input hash. There is no hand-picked block subset or duplicated place to reach twelve. Current inventory has eight: Evanston South, Greenville Downtown, Kenilworth Station, Lakeview Sheil Park, Sloan's Lake, West Highland, Wilmette Vattmann Park and Winnetka Village Green. **Four additional distinct held areas are missing** to reach twelve; no names/datasets are invented and no downloads are performed. Export all eight with the unchanged default exporter, entire-area detail (no focus/profile override), the frozen ladder UTC and the source commit recorded in `world.json`.

Type tags are technical descriptions, not curated truth: first `park/water` if summed source water/pool/park/grass/garden/meadow/recreation/wood area is at least 10% of core area; otherwise `dense grid` if non-part source buildings ≥1,000/km² and ≥70% of core OSM road-segment length lies within 15° of east/west/north/south; otherwise `suburban` below 1,000 buildings/km²; otherwise `mixed`. Overlapping source areas can inflate the park/water sum; rotated grids may be tagged mixed. The tag never changes rendering, camera, thresholds, or selection.

## Renderer and frozen ladder

This scoreboard uses the **existing shipping web world/material, package-lighting, post-processing and near-plane modules in WebGL2 configuration**, through a tooling capture harness. It is separate from the A2 bakeoff and native scores. The bakeoff's regional adapter currently covers Chicago/Denver only; this harness requires no invented Greenville look or region override. Backend selection is explicit and fixed because the existing submitted-pass ledger instruments WebGL2. It does not certify WebGPU or native behavior. Crown v2/v3 and foliage experiments are absent/OFF; no host character, automatic exposure, dynamic resolution, opt-in budget allocator, material override or visibility thinning is added. Package light-state exposure and season are recorded per frame. The existing shipping shadow behavior remains in place.

Reuse `scripts/web_sloans_ladder.json`: 40/150/600 m above the flat export datum, heading 270°, pitch down 45°, vertical FOV 50°, 1,005 × 565 px, DPR 1, UTC `2026-10-15T20:30:00Z`. Sloan's keeps its already-authorized frozen eye (39.7511195, −105.0389); every other block uses its manifest centre by the same deterministic rule. Keep all saved web-pair cameras untouched. Exact WGS84 `LocalFrame` and the existing inspection-camera inverse set direction; shared height near-plane policy is reused. The shipping camera's far plane remains 5,000 m. Exports must explicitly declare flat ground y=0; terrain changes stop until a correct tooling camera adapter exists. Astronomical sunlight comes from each package at this UTC; this differs from bakeoff's fixed calibration light and is declared rather than silently substituted.

Readiness requires all package loading to finish and at least four rendered frames with three consecutive identical submitted-pass counters. Freeze and finish the GPU before taking the frame; no guessed scene-load sleep. Browser/server use an owned ephemeral loopback port and close in `finally`; watchdog cleanup is bounded. Hash-check every exported package file before capture and reject input changes during the run. Record browser version, camera, date, exposure, per-pass counts and PNG hash. Screenshots are local provenance only.

Resolved camera pitch is checked before a scoreboard frame is accepted: reject deviations greater than 2° from either the 45° ladder contract or its pitch annotation. A metadata claim alone cannot pass this guard. See [held-camera audit and Wilmette correction](../review/holdout-camera-contracts.md).

## Automatic technical detectors and thresholds

These are **catastrophic-failure screens, never look grades**. Thresholds are v0 tooling policy chosen before the run, shared across every block/height and recorded in JSON. No threshold adjusts an engine value.

| Check | Measurement / failure threshold | Scope and limitations |
|---|---|---|
| Blank ground | An 81 × 45 pixel-centre ray mask against loaded core static/water geometry and boundary; nearest boundary or `generated-ground` counts blank. Fail **>35% of the frame**. | A mapped park is not blank. Ignores prop/foliage occlusion, so this is a structural upper bound on blank-ground pixels, not a green-color classifier. Sparse samples miss small features. Does not claim that a source-less lawn is intrinsically invalid. |
| Flat frame | After excluding the top 30 px credit strip, sampled RGB-average variance **<4** or range **<10** fails. | Detects empty/flat images even with valid draw counts; no color/style comparison. |
| Water vs source | Source `water` count from independent `worldbake stats` >0 iff a unique exported water feature has nonzero LOD0 ranges. Presence mismatch fails. | Core geometry presence, not visibility from every eye, water appearance, or complete large-water context. `pool` is distinct. |
| Park vs source | Source `park` count >0 iff an exported park feature has nonzero LOD0 ranges. Presence mismatch fails. | Core presence; a park can be behind the camera or occluded. Grass/garden/wood remain distinct kinds. |
| Buildings vs source | Unique exported building IDs with nonzero LOD0 ranges against independent source-loader count of non-part buildings, including accepted Overture additions. Fail absolute relative drift **>2%**; source=0 requires export=0. | Split chunk ranges are deduplicated. Multipolygon pieces sharing one OSM ID can produce a conservative count failure; source count and exported identity count remain explicit. Does not treat offscreen houses as missing. |
| Tunnel surface strip | Core source highway ways with `tunnel` present and not `no`; exclude mapped **pedestrian** `building_passage` unless its source `layer` is negative. Inspect matching exported road/path/sidewalk/crossing vertex ranges in LOD0 GLBs. Any matching range with maximum y **≥−0.1 m** fails. | A pedestrian building passage can have a ground-level floor; excluded IDs remain recorded. Carriageway building passages retain the filed [core guard](../data/tunnel-guard.md). Path kinds match the existing HighwayKind taxonomy. Uses actual geometry heights, not merely road tags. Does not flag separately mapped surface roads crossing a tunnel. Does not audit non-highway tunnels or underground volume quality. |
| Clipping | Ray-mask nearest static geometry lost behind near plane across **≥1%** of samples fails. Also report exact mesh triangle/near-plane intersections, including instances; in-viewport intersection segments **≥2 px** warn. | Intersections can be occluded: an intersection alone is a warning, not a proved visible cut. Static-mask loss excludes instance occlusion; alpha/cutout foliage can have conservative geometric warnings. No clamp or render fix is applied. |

## Budgets and diffs

Sum the existing cost ledger's `main/*`, `shadow/*`, `post/*` buckets separately and require reconciliation with `renderer.info` all-pass totals. Record main and shadow triangles **and draws**, counting actual submitted instances and repeated passes. Evaluate the same default frame against both numeric envelopes; do not rerender different quality settings or infer a phone pass:

- **Floor:** main triangles strictly <400,000; main draws ≤100; all-shadow triangles ≤150,000.
- **Standard (provisional):** main triangles ≤500,000; main draws ≤120; all-shadow triangles ≤180,000.

These are the filed [budget-tiers “Contracts and scope”](budget-tiers.md) boundaries, not raised allowances. No shadow-draw ceiling is filed, so record that metric without inventing a limit. No phone, thermal, memory, shader-time, or visual qualification follows from this desktop run.

The report table is block × height × metric; a separate list records failures and clipping warnings. Diff by stable `area/altitude` keys, listing added/removed rows, numeric changes and failure changes. Changed renderer/exporter code is the subject of the measurement, so it does not suppress a diff; record its input hashes. Changed camera, source, renderer kind, harness or detector contract makes a comparison explicitly non-comparable while retaining its raw deltas. First run reports `first-run`; do not invent a previous run. Raw pixel variance is retained for flat-frame screening but excluded from numeric regression deltas because shipping foliage's wind phase is not pinned; crossing the flat-frame threshold still changes the failure list.

## Validation and execution evidence

New source-inventory, two-attempt stop, tier boundaries, source-change detectors, feature deduplication, types, tunnels, clipping segment and JSON-diff tests accompany the command. Existing capture/near-plane/watchdog/heavy-lock regressions also run under the shared heavy wrapper. Full-run evidence is filed in [world-scoreboard-v0.json](../scoreboard/world-scoreboard-v0.json) and [its generated table/report](../scoreboard/world-scoreboard-v0.md).

Executed on renderer/exporter revision `ee66770`, with exact tooling/source hashes in JSON: **eight blocks, 24 frames, nine preparation/block steps, all first-attempt successes**. Final full run took **522.051 s (8m 42s)** including admission waits, cached preparation, eight fresh exports and captures. The earlier cold/pre-correction run took **1,464.931 s (24m 25s)**, including 103.34 s compilation and other lanes' lock waits. All 1,892 listed package files passed size/SHA-256 checks. All 24 main/shadow triangle/draw counters and structural blank fractions exactly match between runs. The final 47 regression tests pass under the heavy wrapper, including positive synthetic blank/clipping cases; maximum observed admission load in the final run remained below 25.

Results: **0/24 floor and 0/24 provisional-standard budget passes**. Seven of the eight 600 m views fail the >35% structural blank screen; Sloan's is 31.1% and does not cross it. All building counts match source exactly; water and park presence checks pass in every block. No flat-frame failure, static clipping failure or potential-instance clipping warning was found. These statements apply to this fixed desktop WebGL2 workload, not all cameras or devices.

Two below-ground source footways are exported at surface height: **Kenilworth way/206236052 (`tunnel=yes`, `layer=-1`)** and **Winnetka way/323015881 (`tunnel=yes`, `layer=-2`)**. Both have matching path vertex ranges at approximately y=0.05 m, failing the screen at all three heights. This is a core-geometry finding, not a claim that the strips are unoccluded in each image. [The filed guard scope](../data/tunnel-guard.md#implementation) explicitly leaves mapped path/sidewalk ribbons unchanged; no fix is attempted here.

The first run incorrectly flagged Lakeview's three ground-level **pedestrian** building passages as underground tunnels. The general detector correction distinguishes these from actual underground tags/negative-layer passages and retains the filed carriageway suppression policy, including service-road building passages. The three excluded pedestrian IDs remain recorded in the final JSON. [First-run JSON](../scoreboard/world-scoreboard-v0-pre-passage-rule.json) is retained as **pre-correction technical evidence**, not an accepted detector baseline. The final command used it explicitly through `--previous`; the diff records the detector/harness change as non-comparable and preserves raw deltas. Removing that false positive is **not** an engine improvement. Future runs automatically compare the existing final output when `--previous` is omitted.
