# Sources and short quotation register

**Checked 7 October 2026.** Primary sources only for conclusions. Quotes below are short verbatim excerpts; surrounding text is a paraphrase or identifies the source's evidentiary scope. README's WorldEngine-specific classifications are interpretations/proposals, not quotations or provider approvals. Multiple versions/URLs of the same licence are treated as one source. No blocked site was bypassed. This research did not verify every private commercial arrangement or establish a complete litigation register.

## Binding licence and publisher guidance

| ID | Primary source, date/status | Short quotation / why it matters |
|---|---|---|
| L1 | [ODbL 1.0 legal text](https://opendatacommons.org/licenses/odbl/1-0/) — operative licence, checked 2026-10-07 | §3.1: “These rights explicitly include commercial use”; §4.6: “free of charge if distributed over the internet”; §2.3(a): “does not apply to computer programs”. Read §§1, 2.4, 4.2–4.8 and 9 for scope, offers, independent contents and cure conditions. |
| L2 | [OSM copyright/licence page](https://www.openstreetmap.org/copyright) — current publisher notice | “Make clear that the data is available under the Open Database License.” Visual credit/licence link, data-distribution notices and additional-services distinctions. |
| G1 | [Produced Work guideline](https://osmfoundation.org/wiki/Licence/Community_Guidelines/Produced_Work_-_Guideline) — endorsed 2014-06-06 | “intended for the extraction of the original data”. Purpose/accessibility distinction; no GLB-specific example. Its broad publication wording must be read with actual §4.6 and unchanged-data guidance. |
| G2 | [Horizontal Map Layers guideline](https://osmfoundation.org/wiki/Licence/Community_Guidelines/Horizontal_Map_Layers_-_Guideline) — endorsed 2014-06-06 | “the layers for this feature are interacting”. Feature-type independence versus complementary mixed collections; primarily visual 2D guidance, applied cautiously to 3D. |
| G3 | [Collective Database guideline](https://osmfoundation.org/wiki/Licence/Community_Guidelines/Collective_Database_Guideline_Guideline) — endorsed 2016-06-17 | “Two data sets need not be physically separated”. Entire independent property replacement and permissible references are illustrated; mere file separation is not the test. |
| G4 | [Substantial guideline](https://osmfoundation.org/wiki/Licence/Community_Guidelines/Substantial_-_Guideline) — endorsed 2014-06-06 | “repeated small extractions as one big extraction”. One-off qualified examples do not establish a per-tile exemption. |
| G5 | [Trivial Transformations guideline](https://osmfoundation.org/wiki/Licence/Community_Guidelines/Trivial_Transformations_-_Guideline) — **proposal**, not endorsed | “This is at the proposal stage in our process”. Algorithm-only conversion examples are relevant but not a settled exception for inferred spatial records. |
| G6 | [Geocoding guideline](https://osmfoundation.org/wiki/Licence/Community_Guidelines/Geocoding_-_Guideline) — endorsed 2017-08-24 | “Individual Geocoding Results are insubstantial database extracts”. Conditions restrict aggregation; modified underlying geocoder data and public attribution remain relevant. |
| G7 | [Attribution Guidelines](https://osmfoundation.org/wiki/Licence/Attribution_Guidelines) — adopted 2021-06-25; page edited 2026-09-10 | “Attribution must be to ‘OpenStreetMap’.” Surface-specific safe harbour; no dedicated AR rule verified. README proposes the repo's stricter continuous-credit/burn-in practice. |
| G8 | [OSMF Licence / Legal FAQ](https://osmfoundation.org/wiki/Licence/Licence_and_Legal_FAQ) — publisher explanation, not legal advice | “you can simply refer users back to openstreetmap.org as the data source.” Applies to unchanged OSM; §§1.7–1.9 discuss offers, sharing and charging. Guidelines do not replace counsel. |
| G9 | [LWG official page](https://osmfoundation.org/wiki/Licensing_Working_Group) | Contact route and remit. Proposed questions were not submitted. |

The term **Produced Work** describes a finished output (including rendered media, text or sound), rather than a database; it does not establish that a hidden modified database is exempt. Conversely, unmodified OSM used for an image does not automatically require WorldEngine to publish a newly invented database. Treat endorsements as OSMF's guidance, not judicial holdings.

| E4 | [LWG minutes](https://osmfoundation.org/wiki/Licensing_Working_Group/Minutes/2026-03-09) — 2026-03-09 | No quotation. Actual named outreach/escalation discussions, including Hotelmap, EVRI, LinkMyRide and Dopper; no completed court judgment established. |

A primary-source search did not verify a reported ODbL judgment against the named companies. This is a limited research result, **not** proof of no lawsuits, no enforcement or no liability. Termination/cure is separately set out in L1 §9. No US-only exemption is asserted.

| O5 | [Buildings guide](https://docs.overturemaps.org/guides/buildings/) | No quotation. Published ODbL; OSM-priority matching/conflation and potential height merging; building parts OSM-only. |
| O6 | [Divisions guide](https://docs.overturemaps.org/guides/divisions/) | No quotation. Published ODbL; guide describes OSM/geoBoundaries. Other contributors also appear in attribution register. |
| O7 | [Base guide](https://docs.overturemaps.org/guides/base/) | No quotation. Theme declared ODbL although some inputs are independently licensed. A specific independent upstream acquisition is a different product. |
| O8 | [Overture attribution register](https://docs.overturemaps.org/attribution/) | No quotation. Source-level terms include government/custom address agreements; GLOBathy CC0 is marked assumed. Microsoft ML entry conflicts with current upstream licence; do not erase that caveat. |
| O9 | [Overture FAQ](https://overturemaps.org/about/faq/) | “Derivative Database”. OSM-containing themes treated under ODbL; CDLA data/results discussion is not a rule for all themes. |
| O10 | [SourceItem schema](https://docs.overturemaps.org/schema/reference/common/source_item/) | “If omitted, contact the data provider for more license information.” Property-level provenance/licence may differ; a missing value is not clearance. |
| O11 | [2025-09-24 release notes](https://docs.overturemaps.org/blog/2025/09/24/release-notes/) | “To create a purely CDLA-licensed dataset, filter out all records where the source property is ‘Foursquare’.” Specific historical Places filter; new CC0 sources mean a current filter needs fresh review. |
| O12 | [Microsoft Global ML Buildings README](https://github.com/microsoft/GlobalMLBuildingFootprints) | No quotation. Current licence is CDLA Permissive 2.0; listed dataset refresh 2026-08-13. Licence-change date and Overture's exact upstream snapshot unverified. |
| O13 | [Microsoft Global ML Buildings LICENSE](https://github.com/microsoft/GlobalMLBuildingFootprints/blob/main/LICENSE) | “Data in this repository has been licensed by Microsoft under CLDA Permissive 2.0.” Source spells CLDA; linked agreement is CDLA. Applies to direct upstream data, not automatically to Overture's conflation. |
| O14 | [Google Open Buildings](https://sites.research.google/gr/open-buildings/) | No quotation. Direct source offers CC BY 4.0 or ODbL 1.0; licence choice is not a right to relicense filtered Overture tiles. Verify geography/version before choosing it. |
| O15 | [CDLA Permissive 2.0](https://cdla.dev/permissive-2-0/) | §3.1: “no obligations or restrictions on Results”. §2.1 requires licence text with shared Data; applies only to data actually covered by this licence. |

**Unverified legal strategy:** excluding OSM-named records from an ODbL Overture theme is not documented as a general relicensing permission. Source provenance can describe a footprint while heights or conflation come from another input. Prefer direct independently licensed inputs for a permissive-only pipeline, with counsel reviewing lineage and feature/property substitution.
