**Status vocabulary:** **inferred** = conclusion from source-code reading, not demonstrated runtime behavior; **documented** = a repo document or public SDK declaration states it; **proposed** = a recommended change; **unverified** = missing evidence or runtime validation. ## Findings that change the earlier research

1. **Inferred:** the public engine view uses SwiftUI **RealityView**, with a UIKit probe that locates an underlying **ARView** for resolution and snapshots. It is not an application-owned ARView renderer. [WorldView.swift](~/Desktop/world-engine/Sources/WorldEngine/WorldView.swift:167), [RenderControl.swift](~/Desktop/world-engine/Sources/WorldEngine/RenderControl.swift:116).
2. **Inferred:** iOS **26.0 is already the package and WorldLab minimum**, rather than a new change needed for this proposal. Repository rules also document that floor. [Package.swift](~/Desktop/world-engine/Package.swift:6), [WorldLab project.yml](~/Desktop/world-engine/Apps/WorldLab/project.yml:7), [AGENTS.md](~/Desktop/world-engine/AGENTS.md:4).
3. **Inferred:** explicit GPU instances, four building/foliage LODs, merged building tiles, ground batching, foliage view/shadow culling and thermal resolution control already exist. The next work is bounded residency and shared export parity, not implementing these ideas from zero.
4. **Inferred:** the current native draw/triangle gates measure **main-camera frustum estimates**, not all-pass hardware submissions. The earlier research's conservative all-pass reinterpretation was a proposal; it is **not the repo's existing contract**. The visual spec documents separate main and shadow limits.
5. **Inferred:** most tree crowns are now opaque; only the nearby character cut-away slot uses a transparent pipeline. Distant trees are already 12-triangle opaque skyline meshes, so impostors have much less headroom than the generic research example suggests.
6. **Unverified — checkout behind main:** the P1 map-layer changes identified by R are absent from the inspected checkout. This review cannot validate that newer export or NJ's exact fields. The user reports commits `d7b4917` and `74083e5`; neither commit was inspected or verified, because git is prohibited.

## Renderer surface and OS floors

**Inferred:** `WorldView` adds `world.rootEntity` to RealityView, creates a PerspectiveCameraComponent (0.1–5,000 m, initial vertical FOV 50°), subscribes to SceneEvents.Update, and runs the camera/world update there. Motion blur, depth of field and camera grain are disabled. Pause removes the RealityView from the hierarchy. [WorldView.swift](~/Desktop/world-engine/Sources/WorldEngine/WorldView.swift:167), [WorldView pause](~/Desktop/world-engine/Sources/WorldEngine/WorldView.swift:45).

**Inferred:** `RenderSurface.attach` traverses the window's view hierarchy, finds the ARView whose frame best matches an invisible probe, and applies `contentScaleFactor`. The setter is public UIKit, but relying on RealityView's internal view composition is a **runtime integration assumption**, not a direct documented RealityView resolution API. Multiple views or OS changes could affect discovery. No runtime check was performed here. [RenderControl.swift](~/Desktop/world-engine/Sources/WorldEngine/RenderControl.swift:122).

**Inferred:** the governor uses pixels per point, not a fraction of native resolution: nominal 2.5, fair 2.25, serious/critical 2.0, capped by screen scale, with 60 s cooler-state recovery. Heat is checked about once a second. Do not interpret 2.5 as a 250% render multiplier. Hidden/background pausing exists; the `framesPerSecond` property is set to 60 when unpaused and is **not a measured FPS reading**. `gpuFrameMs` can remain nil; WorldLab's actual frame sampling and external Metal traces are separate. [Display.swift](~/Desktop/world-engine/Sources/WorldGen/Display.swift:46), [display.json](~/Desktop/world-engine/Sources/WorldGen/Profiles/display.json:8), [RenderControl.swift](~/Desktop/world-engine/Sources/WorldEngine/RenderControl.swift:178), [Metrics.swift](~/Desktop/world-engine/Apps/WorldLab/Sources/Metrics.swift:38).

## What the limits actually count

**Inferred:** `World.estimateView` constructs a camera frustum (near 0.1, far 5,000 m), intersects world/entity/batch bounds, and sums one draw per visible cell/tile/batch or mesh part. An instance batch contributes `batch.count × batch.triangles` if its aggregate bounds intersect. It does not calculate actual pixel occlusion or per-instance hardware visibility. Estimates refresh twice a second through the world update. [World.swift](~/Desktop/world-engine/Sources/WorldEngine/World.swift:899).

| Counter / gate | Inferred meaning | Omissions / caution |
|---|---|---|
| `viewDrawCalls`, `viewTriangles` | Estimated main-view geometry intersecting bounds; context included | No shadow/depth repetition, post-process dispatches or actual hardware draws; host characters excluded |
| Sky/stars/precipitation in estimate | One draw each when enabled | Their triangles omitted; actual particle/submission costs may differ |
| `drawCalls`, `triangles` | Enabled world geometry aggregate, without main-frustum filtering | Not shadow-inclusive despite the “submitted per frame” comment on triangles; no visibility guarantee |
| `meshBytes` | Logical 56-byte vertices + 4-byte indices plus instance-transform estimates | Not process footprint, texture/RT/driver memory or exact allocated instance capacity; duplicate LOD/tile buffers are included where accumulated |
| `ViewDrawBudgetTests` | `viewDrawCalls <= 100`; `viewTriangles < 400_000` on named 16:9 views | Read-only inspection did not run tests; test can return without shaders/data. These are not measured GPU acceptance results |

Sources: [WorldStats](~/Desktop/world-engine/Sources/WorldEngine/World.swift:36), [recount](~/Desktop/world-engine/Sources/WorldEngine/World.swift:779), [MeshBuffers.gpuBytes](~/Desktop/world-engine/Sources/WorldMesh/MeshBuffers.swift:152), [ViewDrawBudgetTests](~/Desktop/world-engine/Tests/WorldEngineTests/ViewDrawBudgetTests.swift:101).

**Documented repo contract:** v2 §8.1 describes approximately 290k planned **main** triangles, 400k main ceiling, **150k shadow ceiling**, and 100 main-view draws; it also contains an older ≤10 ms GPU target on iPhone 13-class devices. The latest user research context is A16, 60 fps, roughly 13–15 ms with shadows. **Proposed:** R explicitly reconciles the GPU/device target; preserve main/shadow separation rather than silently replacing it with a 400k all-pass triangle gate. [v2 §8.1](~/Desktop/world-engine/docs/proposals/visual-v2/WorldEngine-Visual-Spec-Proposal-v2.md:341).

**Inferred:** the web path resets renderer.info once before post.render / renderer.render, disables automatic resets, then forwards renderer.info.render. Thus it samples accumulated render statistics across that render operation, rather than the native frustum estimate. Inclusion of each shadow/backend/post pass must be checked in the pinned three.js renderer; exact parity is **unverified**. Its values must not be directly compared to native `viewDrawCalls` as equivalent counters. [web main.js](~/Desktop/world-engine/web/src/main.js:48), [web reporting](~/Desktop/world-engine/web/src/main.js:147).

## Trees: opaque versus alpha

**Inferred:** native foliage slots 1–4 are opaque: near outside the cut zone, mid, far, skyline. Slot 0 uses the cuttable material only while a character cut-away target exists, within about 20 m of the camera. Without a target, near instances join opaque slot 1. Diagnostic opaqueDetail can disable this improvement for comparisons. [World.swift](~/Desktop/world-engine/Sources/WorldEngine/World.swift:124), [World.swift](~/Desktop/world-engine/Sources/WorldEngine/World.swift:832).

**Inferred:** cuttable foliage/props use `blending = transparent(opacity: 1)`, opacityThreshold 0.5, depth writes and back-face culling. “Opacity 1” does not make this the opaque pipeline. Buildings and opaque foliage variants do not set transparent blending. Tree lobes are actual mesh geometry; winter leaf removal collapses lobes in the geometry modifier instead of using billboard alpha textures. Skyline crown geometry remains as a bare twig mass. Sway fades between 100–150 m. [RenderResources.swift](~/Desktop/world-engine/Sources/WorldEngine/RenderResources.swift:146), [foliage shader](~/Desktop/world-engine/Sources/WorldEngine/Shaders/WorldShaders.metal:478).

**Inferred:** deciduous tree budgets include mid ≤200, far ≤52 and skyline ≤12 triangles; these are generator ceilings, not a promise that all crown families use identical counts. The skyline trunk is a fixed geometry card, **not a camera-facing textured crown impostor**. [Props.swift](~/Desktop/world-engine/Sources/WorldGen/Props.swift:473), [skyline](~/Desktop/world-engine/Sources/WorldGen/Props.swift:633).

**Inferred:** three.js uses alpha-test cut-away logic in instanced materials; native transparent-pipeline behavior cannot be assumed identical. [web materials.js](~/Desktop/world-engine/web/src/materials.js:180).

**Documented, not rerun:** the repo's GPU attribution note reports the opaque foliage change improved a particular fixed-view matched-clock comparison from 15.37 to 12.41 ms. The document warns these charging/thermal runs are functional guidance, not the intended unplugged acceptance run. Treat the result as a recorded experiment with caveats, not a current broad 24% promise. [gpu-attribution.md](~/Desktop/world-engine/docs/perf/gpu-attribution.md:30).

## Export and P1 mapping gap

**Inferred:** current export is `worldengine.package/1`: 200 m chunks containing buildings and ground, two chunk LODs, stable string feature references, four foliage prototype LODs, 400 m instance cells, hashes and source/license metadata.
