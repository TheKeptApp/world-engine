## “Does it render?” smoke — failures only, no look score

1. Freeze the eligible panel, renderer/device tier, shared recipe, source/package versions and test commit before starting. Run the same A1 pipeline and generator/renderer code for every block; only source, geographic and regional inputs vary. No per-block thresholds, manual terrain repairs, camera rescues or appearance tuning. No acquisition occurs under this docs task.
2. Verify preparation/package loading, then first render and a fixed reproducible traversal per block. Check empty areas, missing chunks/holes, invalid geometry, terrain cracks/spikes or datum jumps, exceptions/crashes and declared main/shadow/draw/memory budgets. Check against each manifest's expected coverage mask: distinguish a known data gap from a new render failure. Heavy execution uses `scripts/heavy.sh` and existing budget checks; unsupported counters are unknown, not zero.
3. Keep execution/coverage metadata and raw evidence internally so “no failures reported” cannot disguise an unrun block. **The report contains failures only:** `commit | block | renderer/tier | failure category | reproduction/capture/log | expected vs actual | owner`. Missing input or an unexecuted required slot is an `INPUT_BLOCKED` failure, not a pass. An all-clear run produces no success bulletin. No closeness, aspect scores, ΔE, aesthetic remarks or aggregate look claims appear in this smoke report.
4. Route source/coverage failures to A1, generation failures to P2, iOS render failures to 5A and bake-off failures to A2. Re-run the same reproduction plus the eligible panel after a general fix. Keep historical failures/evidence; do not suppress them by dropping the block.

## Blind spot-check after each big merge — separate visual report

“Big” means a merge changing shared generation, LOD, terrain consumption, atmosphere/lighting/materials or renderer behaviour across areas. A3 coordinates the check on the lane report; no unattended automation is created.

- Before revealing the selection to implementers, A3 draws **two** blocks without replacement from a pre-registered pool of authorized, prepared, source-cleared blocks outside this named panel and all previously inspected/tuned blocks. This two-block sampling is a proposed operating size, not a statistical guarantee. Stratify the pool by the variety categories above and draw across different categories when possible; publish seed, eligible IDs and selection after the implementation is frozen. Do not cherry-pick by appearance.
- “Unseen” means not previously visually inspected by the implementing lane; log prior exposure. If the available pool is empty, record **blind check pending — no eligible unseen blocks**. No data downloads or new bounds authorization are implied. Do not relabel named Lakeview or other familiar fixtures as blind.
- Capture merge-parent and merged code using identical data, cameras, weather/season, viewport and renderer. Hide commit labels and randomize A/B presentation for grading where practical. A3 applies existing GRADING.md §M closeness and six aspects, with §N changed-frame/noise controls and the approved calibration targets; declare target mismatch/changed fixtures rather than invent a score. No custom rubric and no ΔE substitute. Smoke results stay in their own failure-only report.
- Never tune on a selected blind block: it remains an evaluation case, not a development fixture. Report the defect category without permitting a block-specific adjustment. A subsequent fix must derive from the general rule/data and ordinary development fixtures; retest untouched selected blocks and draw fresh unseen cases for the next big merge. Retire exposed cases from the unseen pool and retain their history. This is a practical anti-tuning protocol, not a claim of statistical independence or guaranteed generalization.
