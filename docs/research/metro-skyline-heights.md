# Metro skyline height readiness

Research snapshot: 8 October 2026 America/Denver (bounded samples taken 9 October UTC). Scope: the 25 largest **US metropolitan statistical areas**, plus eight named follow-ups. Research only; no pipeline, look, raw-data assets or tracker changes.

## Decision and limits

**No metro is certified skyline-ready by this audit.** Overture yielded bounded samples for all 85 cells. OSM yielded three cells before HTTP 429; access stopped immediately, with no retry or alternate-server workaround. Direct Microsoft counts are unavailable: its documented GeoJSONL/gzip regional partitions offered no established bounded spatial sample route. No Microsoft archive was downloaded. The requested complete three-source comparison therefore remains unfinished; unavailable counts are not zero.

The table grades describe a **provisional acquisition route**, not a completed skyline validation. “Needs one extra source” means adding one permitted source family, normally public USGS LiDAR, to the existing height ladder; it can require multiple workunits, dates and jurisdictions. Exact roof coverage for every district remains pending. “Blocked” means this audit has not established a permitted replacement route. “Skyline-ready from open data now” would require verified tall-building completeness, valid roof heights, applicable rights and joins in every target district; none meets that evidence bar here.

A count of source records whose recorded height exceeds 30 m cannot identify tall buildings with missing or wrong heights. These are source-signal counts, **not recall, missing-tower counts, or a census of buildings over 30 m**. Representative square cells do not cover entire districts or every tall-building cluster. No population-wide height or accuracy conclusion follows from the samples.

## Sampling protocol

Cells were fixed before queries. Each is approximately 1 km square: latitude half-width `500/111320` degrees; longitude half-width divided by cosine of centre latitude; bounds rounded to six decimals. Bounds appear below, ordered west/south/east/north. Inclusion is source bbox intersection, not identical physical-building matches. No block-specific exceptions or hand-picked buildings.

* Overture: cloud GeoParquet range reads, building type only; bbox intersection; exclude explicitly underground records; sort by GERS `id`; take first 200, requesting 201 only to detect the cap. Read `id`, `height`, `sources` and filter columns, not geometry. No complete parquet file fetched. Enforced limits: 2 MiB per range, 8 MiB per cell, 160 MiB overall; require HTTP 206, stop on access errors. Actual range transfer: 136,611,389 bytes across 821 requests, with reuse/cache; zero complete bulk archives downloaded. [Official filtered cloud access](https://docs.overturemaps.org/getting-data/cloud-sources/); [pinned STAC licence/release](https://stac.overturemaps.org/2026-09-23.1/buildings/building/collection.json).
* OSM: `wr["building"]["building"!="no"]["building:part"!~"."](south,west,north,east); out tags asc 201;` with JSON output and 20-second timeout. First 200 source records in API order. Pure/dual-tagged parts excluded; ways/relations not physically deduplicated. OSM tag responses were transiently parsed for heights only; any unrelated/address tags were discarded. No owner, address, personal metadata or feature IDs retained in the document. [Overpass resource policy](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html) respected after 429.
* Valid height: numeric `0 < h < 1000 m`; tall signal: strictly `30 < h < 1000 m`. OSM accepts explicit metres/feet and converts feet by 0.3048. No defaults or floor-count substitution. Counts do not establish correct height, roof definition or unit accuracy.
* `T/H/N` = records with >30 m height / valid heights / sampled records. `*` means a 201st record existed, so the sample is capped. ND-R = not obtained after OSM rate limit; ND-B = direct Microsoft bounded route not established. Different source order/coverage means cross-source ratios are not matched-building comparisons. Adjacent/overlapping cells must not be summed as unique buildings.
* The optional **MS-in-Overture proxy** is a subset of Overture T with explicit Microsoft-only attribution for `/properties/height`, or Microsoft-only generic attribution when no property-specific attribution exists. It is not a current direct Microsoft sample, and must never fill the direct Microsoft column.

## What A1 should do next

Freeze these cells and the footprint snapshot before comparing the ladder. Form a common building frame with stable footprint IDs and deterministic hashed selection of up to 200 per cell; include missing-height records, rather than selecting only known >30 m records. Join source geometries by overlap/centroid with explicit one-to-many and building-part ambiguity flags; never assume GERS, OSM IDs and assessor parcel IDs are equivalent. Publish aggregate matched, unmatched, valid-height and ambiguity counts. An independently established tall-building frame is needed to measure >30 m recall; this audit does not supply that ground truth. Do not hand-pick landmark exceptions to improve metrics.

Add only cleared public roof/ground data after confirming per-cell flight epoch, density, building classifications and coordinate/vertical units. Use a fixed roof statistic and ground subtraction rule. LiDAR contributes roof/ground measurement error, registration, vegetation contamination, roof-equipment/part-definition error and survey lag; ground-control RMSE is not building-height RMSE. Report independent storeys as categories unless conversion is separately calibrated; modelled ML average height is not maximum skyline height. Existing lidar-derived fallback versus lidar-derived reference has correlated error. Denver stereo and administrative floor counts are possible independent references only once exact release rights and definitions are cleared; they are not used here.

To certify readiness, separately inventory post-survey towers and tall-building parts, verify every target district rather than central-box intersection, and clear redistribution of the delivered assets with A11. Repeating source-only capped counts cannot establish skyline accuracy. Rerun OSM only when normal access is permitted; obtain a publisher-supported bounded Microsoft route or leave direct counts unavailable.
