# Agent data angle: scoping research

9 October 2026. Read-only audit; no engine, API, data acquisition or release change. Repository baseline `c08d7bb`. **Best candidate: a Chicago/Lakeview pilot selling convenient, versioned geometry plus evidence and processing.** Existing open sources can reproduce the underlying facts. Five query opportunities below are hypotheses, not five demonstrated competitive wins. No customer query benchmark or deployed agent API exists in this audit.

## Five candidate agent queries

Every query requires a new API adapter; “data-backed” means evidence already exists locally, not that the query is implemented. Advantage is the saved integration work and explicit uncertainty. A developer could build similar joins from free sources; we have not measured willingness to pay, latency or superiority against a well-configured GIS.

| Query | Input | Output | Why a joined service could win / current boundary |
|---|---|---|---|
| 1. Evidence-aware building envelope | Snapshot ID, AOI bbox, optional height threshold, `observed_only` | Footprints plus observed roof/eave AGL, source survey/date/method, D grade, null interval, missing count; generated render values in separate fields | Lakeview has 2,618 accepted observations versus 0 explicit OSM height tags in its buffered input. Avoids the caller finding LiDAR, subtracting ground and joining it. **Data-backed**, uncalibrated; not clearance or engineering certification |
| 2. Roof-form summary with abstention | Snapshot ID, bbox, requested form classes | Counts and fractions for flat/gable/hip/other/missing, denominator, acquisition dates and heuristic/calibration status | Free footprints/optional height are not a prejoined roof-form analysis. New Lakeview table has 2,563 non-missing forms. **Data-backed**; mixed roof conventions and limited validation must be visible |
| 3. Evidence versus fallback audit | Snapshot ID, bbox, fields required, maximum accepted evidence age | Observed/inferred/missing counts, stale-observation flags, source licences and geometry/population mismatch warnings | Gives an agent a deterministic basis to abstain instead of silently equating profile height with measurement. **Data-backed**, but exporter provenance needs an adapter and reconciliation; no current calibrated confidence claim |
| 4. Appearance-aware building selection | Snapshot ID, bbox, generated building role/family or paint filter; optional surface-role request | Generated house/block/garage/shed, family, paint and front-edge fields; origin marked inferred; `unsupported_field` for physical materials or A4 surface roles | Saved role/appearance joins are convenient for visual-scene agents and usually absent in source maps. **Partly data-backed**: all Lakeview buildings have a generated role; roof/wall/trim/door surface querying remains blocked on A4 implementation, and true physical material is unknown |
| 5. Reproducible scene-context inventory | Snapshot ID, bbox, layers requested, feature budget | Distinct buildings/roads/paths/water/ground classes, footprint geometry where available, source versus generated flags, version/credits and capped/paginated results | Agent receives one frozen, consistent scene inventory rather than assembling several live queries. **Data-backed for saved Sloan/Lakeview outputs**; visual land-use/sidewalk classes are not authoritative parcels or a validated routing network |

## Minimum one-metro API / MCP specification

**Chicago pilot, Lakeview 1 km² only.** Advertise this exact AOI, not Chicago-wide coverage. Choose and freeze one canonical footprint population; reconcile the 2,799 new-evidence versus 2,823 legacy-render population with deterministic joins and explicit unmatched records. Never silently overwrite observed nulls with profile or Microsoft heights. Wilmette is a later expansion after a package/export audit.

Provide a read-only REST layer with an MCP adapter over the same queries. Start as internal local stdio; remote delivery is a later deployment decision subject to the public-data obligations above. Pin a stable MCP protocol/SDK compatible with target clients; [2025-11-25 tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools) is the documented baseline here, and any newer release must be assessed before implementation. JSON Schema inputs, structured outputs and accurate read-only/idempotent annotations; annotations are hints, not authorization controls.

| Endpoint / MCP tool | Minimum contract |
|---|---|
| `GET /v1/areas` / `area_capabilities` | AOI bounds, snapshot/version/hash, supported layers/fields, data dates, counts, licence/credits/offer URLs, unavailable fields |
| `GET /v1/buildings` / `query_buildings` | Bbox, optional IDs/role/height filter, observed-only switch, field whitelist and cursor; GeoJSON footprints plus separate observation/render fields |
| `GET /v1/height-summary` / `summarize_height_evidence` | Bbox and optional form/age filter; counts, observed-only height quantiles, explicit denominator, missing/stale fractions and calibration status; empty observed subset yields null statistics |
| `GET /v1/layers` / `query_map_layers` | Bbox, allowlisted roads/paths/water/ground/generated layers; stable feature IDs, geometry and source/inferred flag, pagination |
| `GET /v1/provenance` / `get_provenance` | Snapshot and feature/field reference; source release/survey, method, units/datum, join evidence, quality grade, limitations and licence links |

Every result carries `snapshot_id`, `schema_version`, `bbox`, `returned_count`, `truncated`, `next_cursor`, provenance references and notices. Height observation: `roof_top_agl_m`, `eave_agl_m`, `evidence_kind`, `quality_grade`, `interval90_m`, `calibrated`, source/date/method; use **D / null / false** for the audited new observations. Generated output uses separately named render height, floors, building role, colour and family with an inference marker. Unknown physical materials remain null; unavailable A4 surface roles produce a supported-field error, not an invented role.

Use WGS84 GeoJSON externally with explicit projection/conversion from local engine coordinates; AGL in metres, not NAVD88 absolute elevations. Deduplicate scene fragments by canonical feature ID; decide geometry ownership before exposing clipped fragments. Bound requests to the declared AOI, default 100 features and maximum 1,000, with a proposed 1 MiB response cap and cursors. No arbitrary SQL, remote URLs, source acquisition or engine execution from a query. Whitelist structural fields; do not forward raw source tags wholesale. Remote service would add client authentication, Origin checks, request/byte budgets and minimal operational logs.

Acceptance: frozen full-AOI aggregates reproduce this audit or document population reconciliation; missing is never zero; observed-only excludes generated values; provenance distinguishes epochs/units and preserves D/null intervals; unsupported roles fail explicitly; deterministic pagination has no duplicate fragments; every response supplies applicable notices. Test these properties with fixtures and one MCP client, then record latency/bytes under the fixed caps. No SLA or accuracy number is promised before measurement.

| Work for an internal Lakeview prototype | Agent-days, estimate |
|---|---:|
| Freeze canonical population, reconcile source/render joins and field provenance | 2–4 |
| Spatial index and bounded REST queries / aggregate views | 2–3 |
| MCP adapter, schemas, capability discovery and sample client | 1–2 |
| Correctness, pagination, uncertainty/notice tests and basic performance measurements | 2–3 |
| Packaging, documentation and reproducibility handoff | 1–3 |
| **Total internal prototype** | **8–15** |

One agent-day means roughly one focused working day; estimates are additive effort, not elapsed time or benchmarked throughput. Remote hosting/auth/operations adds an estimated **3–6 agent-days**. Counsel review, a working public-data offer, independent height calibration, full-metro acquisition and A4 surface-role implementation are outside these estimates. The internal prototype can evaluate convenience; an external paid pilot requires the separate release conditions. Recommended next evidence is a fixed query comparison against raw OSM/Overture plus a joined GIS, measuring answer completeness, uncertainty handling and caller effort before claiming a moat.
