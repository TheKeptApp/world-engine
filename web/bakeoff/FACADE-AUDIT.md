# Façade audit — report only

No building, yard, export or generator code was changed. This audit distinguishes a missing generator feature from a feature absent in the two frozen exports. The painted reference is not evidence that a real building has a bay or stoop.

| Detail | What the code actually supports / what is missing | Owning pack / implementation evidence |
|---|---|---|
| Brick | Per-building brick colour choices, contrasting foundation/trim, stone openings and reveals exist. Individual brick bonds/course/mortar geometry is not implemented in the inspected generator or web material code. These frames therefore read as large matte wall fields. Fine grain is expressly prohibited by calibration v2; subpixel courses must be omitted rather than painted as noise. | `house-archetypes-v1/archetypes[].colourVariations` and `detailTiers` own material identity/LOD; `house-contrast-v1` owns brick/trim/soffit separation; `style-b-calibration-v2/sharedLook.materials.surfacePolicy` takes precedence for surface simplification. `Sources/WorldGen/BuildingGenerator.swift` brick-wall selection and `stoneOpenings`. |
| Bay windows | Mapped and inferred box/angled bays, multi-storey openings, caps and side bays already exist. The missing item is reliable building-specific bay coverage in these exports, not a missing bay generator. Inferred bays require a suitable family/front edge, room beside the entry, roof clearance and a clear 2.5 m front zone; depth is capped at 0.6 m. Exact reasons for each absent bay require a separate per-building/export audit. | `house-archetypes-v1` form/detail tiers; `house-details-v1` family identity; `Sources/WorldGen/BuildingFacades.swift` `planBay`, `mappedBays`, `emitBay`. |
| Stoops | Raised bases, steps, cheek walls and rails already exist. Mid LOD deliberately collapses risers to a wedge and drops uprights/relief. The mock’s continuous detailed entry rhythm is absent from the frames, but that is not proof that the code lacks steps or rails. Family assignment, frontage clearance and export LOD need diagnosis before new geometry. | `house-details-v1` family steps/cheeks/rails and 10/25/50 m detail policy; `house-archetypes-v1` raised-base/entry forms. `Sources/WorldGen/HouseDetails.swift` `addStair` and `BuildingGenerator.swift` stoop branch. |
| Fences | Low iron front fences, wood rear fences, posts, rails and bars already exist. Their continuity is conditional on yard rules and raster clearance, and they are clipped around hard-use routes. Rich ornamental gates/finials are not implemented in this simple fence builder; the mock’s unbroken fence layout cannot be inferred as real data. | `house-archetypes-v1/streetContexts (fences_walls)` (conditional regional yard policy); `house-details-v1` fenced-setback identity. `Sources/WorldGen/Yards/YardRules.swift`, `YardGeneration.swift` fence placement and `addFence`. |

Recommended next ownership: P2 audits family selection, LOD and generation/export coverage; 5A owns shared colour/shading. No façade geometry is added by this A2 change.
