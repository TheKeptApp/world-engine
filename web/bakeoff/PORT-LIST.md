# Web recipes for 5A / P2 to port or reconcile with iOS

Docs-only handoff, 8 October 2026. Implementation snapshot: **355c6fb**, with paired verification at **4127a32**. All web paths below are relative to this folder; native paths are repository-relative. These recipes worked at the stated mechanism/budget level. They are **not an A3 visual acceptance or an iOS-parity claim**. Latest A2 grade remains pending in [grade.json](evidence/shadow-colour/grade.json); earlier A3 scores are in [web-baseline.md](../../docs/lookloop/web-baseline.md). No native test below has been run by this documentation change.

Port by data, species, region, date and view-independent policy. Keep real geometry and mapped attributes; never fit one camera. For each port, verify the cited source, adapt to native units, run its test, then render Sloan followed by untouched Lakeview and request A3's before/after grade under the frozen contract. Also retain the required wider hold-out gates. If a source or renderer conversion cannot be traced, stop and log the handoff under the [owner's port rule](../../docs/tracking/weekend-brief.md). 5A owns native shaders/light/water; P2 owns generator geometry. **THREE.JS-SPECIFIC** below means an implementation dependency, not necessarily an effect impossible in RealityKit.

## 1. Regional haze and mountain retention — 5A

- **Value / rule:** summer-clear Front Range MOR **75 km**, extinction **0.000039943097 m⁻¹**; Great Lakes/Chicago MOR **20 km**, **0.000149786614 m⁻¹**. Use `sigma = -ln(0.05)/(1000 × visibilityKm)`, `T = exp(-sigma × distanceM)` and **one** linear mix `T × lit + (1-T) × air`. Clear daytime airlight **#BDD0D9**, time mix **0**. Mountain contrast retention **0.05**, fade/cull **0.03–0.05**, internal-detail threshold **0.10**, minimum projected relief **2 px**, with real DEM position and unoccluded curved-Earth sightline. No mountain enlargement; no extra cyan distance grade.
- **Source:** `docs/proposals/haze-visibility-v1/values.json`: `regions[id=front-range|great-lakes].seasons.summer.clear`, `definition`, `airlight.stateDayHex.clear`, `airlight.timeMix.day`, `integration.applyOnce`, `mountains`. [Compiled source subset](data/haze-values.json) retains provenance. This approved pack replaces the old 0.0008/m fixture.
- **Web assumption:** distances in metres; sRGB hex decoded to linear RGB before mixing; fixture requests summer-clear atmosphere independently of its October phenology date. Homogeneous fallback only: unsupported layer inputs are rejected. Sky and already-atmospheric reflection bypass a second mix; DEM uses the same extinction in its explicit contrast-gated shader path. Pixel tests use drawable height at DPR 1.
- **RealityKit difference:** reconcile `Sources/WorldEngine/Shaders/WorldShaders.metal/atmosphere` and `opticalDistance` and `Sources/WorldEngine/Environment.swift`; the inspected native shader has combined clear-air/weather terms and a `ln(10)` fog-end convention, so simply substituting a distance would not implement the new 5% MOR. Preserve a single total airlight integration and inspect where native PBR/emissive terms are combined. Use native drawable pixels, not UIKit points. **THREE.JS-SPECIFIC:** TSL `scene.fogNode` and node-output bypasses; transfer the equation, not these APIs. Layered atmosphere and cloud-obscured summits require their own native ray integration.
- **File / commit / evidence:** [atmosphere.js](atmosphere.js), [backdrop.js](backdrop.js), [main.js](main.js) — **b012b71**, retained at **355c6fb**; [atmosphere.test.mjs](atmosphere.test.mjs) and [HAZE-REPORT.md](HAZE-REPORT.md). The real ridge remains much lower/weaker than the painted mock; retention is not proof of visual closeness.
- **One-line proving test:** Native linear readback must yield `T(75,000 m)=0.05` / `T(20,000 m)=0.05` for the two regions, leave sigma unchanged at night, and pass the contrast/size/occlusion cases already asserted in `atmosphere.test.mjs` before paired A3 review.

## 2. Species crown shapes and trunk ratios — P2

- **Value / rule:** reuse P2's five crown layouts: **10** near lobes, **5** middle lobes scaled **1.1**, and a far ray-to-last-lobe-exit envelope; no single spherical replacement. `(trunkRadius, trunkTop)` fractions of unit tree height: rounded **(0.026, 0.36)**, pyramidal **(0.024, 0.30)**, vase **(0.030, 0.30)**, open **(0.028, 0.37)**, upright **(0.024, 0.33)**. Species spread/height selects width, with P2's **0.6–1.2** clamp. Scale the unit mesh to exported height in metres; tagged exports' already-applied width stretch must not be applied twice.
- **Source:** **fcda086** `Sources/WorldGen/Props.swift` (`lobes`, `deciduous`, conifer construction and normal rules), `Sources/WorldGen/Foliage.swift`, and `Sources/WorldGen/Profiles/vegetation.json/foliageSeasons`; [data/p2-crowns.json](data/p2-crowns.json) `shapes.*`, `foliageSeasons.*`. `foliage-seasons-v1/species[].dimensionsM` supplies botanical dimensions; explicit exported species wins over inferred city/form fallback.
- **Web assumption:** lobe coordinates/radii and trunk ratios are dimensionless; exported scale is metres. Linear vertex leaf/bark colours are lit later. Near cube-sphere and middle/far icosahedral tessellation are web approximations of P2's form and blended normals, not a byte-identical Swift mesh port.
- **RealityKit difference:** these shapes originated in P2; reconcile with the existing generator rather than adding a duplicate generator. Preserve mesh winding, normal smoothing, species identity and one width application. Native instance/LOD machinery differs. **THREE.JS-SPECIFIC:** `BufferGeometry`, `mergeVertices`, `InstancedMesh` and the chosen primitive tessellation. Coarse lobes remain a visible web weakness; do not port that coarseness as an approved target.
- **File / commit / evidence:** [foliage.js](foliage.js), [species-policy.js](species-policy.js), [data/p2-crowns.json](data/p2-crowns.json) — **e73515d**, colour/instance changes at **355c6fb**; [overnight.test.mjs](overnight.test.mjs) validates shape data and all exported species resolution.
- **One-line proving test:** For the same species/height/seed, compare native near/mid/far crown bounds and trunk ratios against the cited layout from several directions, verify width is applied once, and confirm mapped species survives every LOD transition.

## 3. Species and individual crown colour mix — P2 + 5A

- **Value / rule:** interpolate decoded linear colours with date-derived spring/summer/autumn/winter weights; evergreens retain summer. Keep regional autumn orange maple **#CE763C**, russet oak **#A55835**, yellow linden **#C6B24E**, elm **#BCAE4D**, honey locust **#D2B95C**, cottonwood **#C8AC46**. Denver slot lags retain **0.55**, **0.50**, **0.70** of the autumn weight as summer green for linden, honey locust and elm respectively. Individual timing shifts are stable **±7 days**, applied to the day of year. Replay date **2026-10-08** is a test input, not a fixed production season or an observation.
- **Source:** `foliage-seasons-v1/species[].seasonColours` for spring/summer/evergreen and fallback; **fcda086** `Sources/WorldGen/Profiles/vegetation.json` `species` colours, `regions.denver.slots` and `Sources/WorldGen/Foliage.swift/applyingFoliageSummer` precedence; `Sources/WorldEnvironment/Phenology.swift` `treeShiftDays`, `timingSalt`, `denverDemo`, `chicagoland`, `resolve`. [Compiled data](data/p2-crowns.json) `vegetation`, `vegetationRegions`, `phenology` records the exact tables. Several foliage-pack peak colours are the same gold: the regional native autumn palette is an explicit precedence choice, not a claim that those orange/russet values come from that pack.
- **Web assumption:** convert hex to linear before interpolation; the one shared grade follows lighting. `leafTint` affects leaves only; bark is separate. Calendar ordinals use the replay's date string, and identity is seeded through [stable-random.js](stable-random.js) using `inst.id + '/phenology-timing-v1'`. No new draws are introduced for colour variation.
- **RealityKit difference:** reuse the existing regional calendar/vegetation implementation, including the observer's timezone and stable native placement identity. The web seed string is not guaranteed to produce the same per-tree random value as native `OSMRef.random(Phenology.timingSalt)`; do not reroll native trees just to imitate it. Match the distribution and precedence. **THREE.JS-SPECIFIC:** per-instance TSL `leafTint`/`leafMask` attributes and the web loader's rebucketing wrapper; use native palette/instance storage.
- **File / commit / evidence:** [foliage.js](foliage.js), [phenology.js](phenology.js) — **355c6fb**; earlier calendar tests in [overnight.test.mjs](overnight.test.mjs); paired images and provenance in [SHADOW-COLOUR-REPORT.md](SHADOW-COLOUR-REPORT.md). Mixed colours are visible; native visual acceptance is pending.
- **One-line proving test:** With fixed IDs, render dates across green/colour/drop stages in both regions, assert weight sum 1 and repeatable ±7-day variation, retain green evergreens and independent bark, then have A3 assess the untuned mixed-colour pair.

## 4. Shadow caster distance, simpler trees and budget halving — 5A + P2

- **Value / rule:** start at **120 m** horizontal caster radius; trees cast their existing **LOD 2** silhouette while visible geometry stays at its normal LOD. Keep static triangles whose horizontal bounds intersect the radius and prop origins inside it. Count the entire potential shadow submission; if above **150,000 triangles**, halve the radius and rebuild until within budget. No scene/camera-specific preset. The halving algorithm is an A2 implementation choice, not a pack value.
- **Source:** `Sources/WorldGen/Profiles/look.json/shadows.rangeM=120`; R's floor clarification, recorded in [budget.js](budget.js) `phoneBudget.shadowTriangles=150000`; implementation in [shadow-casters.js](shadow-casters.js). Other floor caps remain **400,000 main triangles**, **100 main draws**; all passes must be reported.
- **Web assumption:** radius is horizontal world metres around the current camera; material-independent shadow proxies use a separate light-camera layer. The current single-light single-shadow-pass captures produce Sloan **5,008 triangles / 17 draws**, Lakeview **67,190 / 81**, both at **120 m**. These captures did **not** trigger the halving branch. Proxy rebuilding during navigation and adaptive transitions have not been qualified.
- **RealityKit difference:** `Sources/WorldEngine/Environment.swift` already manages native shadow range, low-sun extension and far canopy shadows; `World.updateLODs` keeps relevant off-view casters. Preserve that receiver/sun-aware behaviour rather than assuming a radial cut is sufficient at low sun. A native maximum-distance setting is not a triangle-budget guarantee. Count every native shadow cascade/light pass, avoid drawing proxies in the colour pass, and verify actual native culling. **THREE.JS-SPECIFIC:** shadow-camera layer **1**, colour layer **0**, `castShadow`, back-face material setting and the WebGL draw ledger. Apple's current shadow-layer/cascade APIs include beta entries: verify availability in the project's installed SDK; no unverified API substitution is prescribed. [Apple shadow API](https://developer.apple.com/documentation/realitykit/directionallightcomponent/shadow).
- **File / commit / evidence:** [shadow-casters.js](shadow-casters.js), [main.js](main.js), [budget.js](budget.js) — caster implementation **355c6fb**; [phone-budget.json](evidence/phone-budget.json), [rebase-check.json](evidence/shadow-colour/rebase-check.json) at **4127a32** prove the captured all-pass floor result, not adaptive halving or phone performance.
- **One-line proving test:** On native, force a dense scene over 150k shadow triangles and verify successive radius halves bring the sum of every shadow pass under 150k while visible meshes remain unchanged, then repeat both frozen views and a low-sun/off-view-caster case.

## 5. Lake colours, shore and broken reflections — 5A only

- **Value / rule:** deep **#477C8D**, shallow **#668C82**, **2 m** shallow blend; water-side shore multiplier **0.88 → 1** over **0.6 m**, with no extra land darkening or shoreline movement. Wind-10 fixture: roughness **0.28**, normal amplitude **0.08**, wavelength **0.8 m**, phase speed **0.6 m/s**. Sky reflection modulates lake luminance while retaining lake chroma; this is a stylized rule, not physically complete coloured reflection. Pack normal/grazing reflection weights **0.12/0.55** and exponent **5** remain bounded by the water-surface caps.
- **Source:** `lake-winter-v1/lake-winter-values.json`: `states[id=sloans_lake_clear_wind_10].surfaceValues[0].baseColourHex`, `water.profiles.sloans_lake.{shallowColourHex,shallowBlendWidthM,waveByWindKmh}`, `water.windStates`, `water.shoreline`, `water.reflection`; `water-surfaces-v1/water-values.json` `reflectionLimits`, `waveModelProposal.fourWaveWeights`. The latter mechanics do not supply the lake's palette. [water.js](water.js) derives shore distance from exported boundary edges, not an unrelated exported attribute.
- **Web assumption:** metre-valued **1024² R16F** shore-distance texture replaces the quantized 8-bit field. The current material treats the authored colours as neutral-witness appearance targets: [sky-colour.js](sky-colour.js) inverts the web's shared grade, then `main.js` divides by known RGB Lambert-witness irradiance. Physical light/normal response remains; reflection uses a sky-luminance ratio without replacing the pigment's chroma. This is the A2 conversion that reduced cyan in the inspected image; it does not redefine the pack's base-colour semantics.
- **RealityKit difference:** native `WorldShaders.metal` has its own lake material and `PostProcess.swift`/`OffscreenRenderer.swift` determine the output transfer. Decode palette hex once; establish whether the native input is albedo or appearance before applying any compensation. **THREE.JS-SPECIFIC — DO NOT COPY NUMERIC CONVERSION:** inverse ACES-fit coefficients, the **0.6** fit normalization, web irradiance division, TSL `outputNode` fog bypass and its sky texture are tied to this web pipeline. Re-derive a native conversion only from its verified response, or use native albedo directly if it meets the witness target. A Metal metre-valued distance texture is a viable implementation direction, not a tested native port. The pack's separate **0.4 m** wet-bank transition is not established by this water-only web treatment.
- **File / commit / evidence:** [main.js](main.js) water block — **355c6fb**; [water.js](water.js) floating-point shore field — **80ed32c**; [sky-colour.js](sky-colour.js) — **7be4857**; local [Sloan comparison](evidence/shadow-colour/sloans-before-after.png) and current metadata [sloans.json](evidence/candidate/sloans.json). The web grade inverse has round-trip tests; native colour/reflection equivalence is unproven.
- **One-line proving test:** Under the native neutral witness, read back deep/shallow and 0–2 m shore samples through the actual display transfer, verify a smooth metre-scale gradient and a single airlight mix without cyan bleaching, then compare the frozen water view with A3.

## 6. Neutral shadow-to-lit witness and one grade — 5A

- **Value / rule:** neutral horizontal witness `Yshadow/Ylit = 0.62`; ambient visibility floor **0.65**. Calibration sun **#FFE8C6**, sky fill **#AEBCCA**, fixture sun elevation/azimuth **40°/225°**. Apply **+0.35 EV**, linear gain **1.2745606273192622**, saturation **1.08**, contrast **1.06** once; no city override. The ratio is a linear-light witness target, not a screen-pixel brightness ratio or a literal key/fill intensity quotient.
- **Source:** `style-b-calibration-v2/values.json` `sharedLook.lighting.{sun,sky,shadow,exposure}`, especially `shadow.neutralWitnessShadowToLitLinearY`; `docs/look-spec-changes.md` for hue-preserving luminance tone mapping. Native `Sources/WorldGen/Profiles/look.json/daytimeMaster` gains are native calibration values, not WebGL units.
- **Web assumption:** [lighting.js](lighting.js) uses `directIntensity = pi × directRelative`, `directY = directIntensity × Y(sun) × sin(elevation)`, `fillIntensity = directY × 0.62/(1-0.62)/Y(fill)`. A same-colour sky/ground HemisphereLight supplies the fill. Linear Rec.709 luminance is **(0.2126, 0.7152, 0.0722)**; the installed three.js ACES fit is applied to luminance, followed by the single saturation/contrast grade. Existing soft PCF shadows remain.
- **RealityKit difference:** directional light intensity is photometric (lux); native `Environment.swift` multiplies its own exposure/direct gains by `sunLux`, while `WorldShaders.metal` supplies emissive hemispheric fill and IBL contributes separately. Measure their combined response; do not paste the web pi/intensity result into native light intensity. Native offscreen tone mapping is enabled, and custom postprocessing is separate: ensure exposure/saturation are not applied twice. **THREE.JS-SPECIFIC:** HemisphereLight's irradiance convention, PCF filter and the ACES-fit inverse; the ratio and pack colours are transferable targets. [Apple directional light](https://developer.apple.com/documentation/realitykit/directionallightcomponent), [Apple postprocessing](https://developer.apple.com/documentation/realitykit/postprocessing-effects).
- **File / commit / evidence:** [lighting.js](lighting.js), [sky-colour.js](sky-colour.js), [main.js](main.js) — **7be4857**; [overnight.test.mjs](overnight.test.mjs) proves the analytic ratio at several elevations, [sky-colour.test.mjs](sky-colour.test.mjs) the grade round trip. Neither is a native rendered witness test or proof that the light step improved A3's grade.
- **One-line proving test:** Render an unoccluded neutral Lambert patch and its fully key-shadowed counterpart on native, measure pre-grade linear Y ratio 0.62 with AO/extra occluders controlled, verify one grade and stable hue, then submit the same untuned scene pair to A3.

## 7. Facade detail by family, era and projected size — P2 + 5A

- **Value / rule:** projected building height **≥20 px near**, **6–20 px middle**, **<6 px far**; cull thin features below **1 px**. Near adds shallow courses/trim/stoop/fence geometry; middle keeps bays, porch/stoop mass and cornice silhouette; far keeps envelope/roof/broad colour. Preserve mapped colour, footprint and height; known `start_date` selects the pack era palette, unknown era retains family colour. The metric is projected size, not a fixed camera-specific distance.
- **Source:** approved `facade-detail-v1/values.json` (copied to [data/facade-values.json](data/facade-values.json)): `lod.{nearMinPx,middleMinPx,farBelowPx,featureCullBelowPx}`, `content.families`, `content.eraPalettes`, `content.details`. Dimension ranges stay in metres. [data/facade-mechanics.json](data/facade-mechanics.json) identifies native-derived dimensions separately from A2 construction choices; its **0.08 m** course pitch, **0.005 m** joint and **0.035** contrast are authored adapter choices, not pack measurements.
- **Web assumption:** `px = heightM × drawableHeightPx / (2 × tan(verticalFov/2) × distanceM)` in [facade-policy.js](facade-policy.js); DPR 1 makes CSS and drawable pixels coincide in captures. Road geometry chooses frontage, not camera position. Courses use shader derivatives to suppress subpixel marks. Detail batches use **400 m** cells from P2 `Props.swift/cellMeters`. This tiers the added facade detail; it does not simplify all existing static export chunks. The pack's **0.1** hysteresis fraction is not implemented by the stateless web tier selector.
- **RealityKit difference:** use actual native drawable resolution and camera projection, including any resolution scaling; UIKit points are not the pack's pixel unit. Reuse existing P2 bay/stoop/fence generation and avoid duplicating already-exported detail. Native material/mesh batching and derivative access need a native implementation. **THREE.JS-SPECIFIC:** TSL `fwidth`, node wall colours, geometry merge/batching and current resize-driven updates. Native motion/hysteresis must be qualified separately. Only greystone/brick-two-flat/bungalow/foursquare vocabulary is covered; sixFlat is partial adaptation and other families remain uncovered, as counted in [the audit](SHADOW-COLOUR-REPORT.md).
- **File / commit / evidence:** [facades.js](facades.js), [facade-policy.js](facade-policy.js), [compile-facade-data.py](compile-facade-data.py) — **5a373b7**; [overnight.test.mjs](overnight.test.mjs) checks mapped-colour priority, unknown-family refusal and tier selection; paired capture metadata records actual generated detail.
- **One-line proving test:** Sweep one native building through the 20/6/1 drawable-pixel thresholds and multiple resolutions, checking tier/feature removal without altered footprint/height or duplicate details, mapped-colour priority and untuned A3 review of both views.
